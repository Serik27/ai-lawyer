🇺🇦 AI Legal Assistant (AI-Юрист) System Documentation

ШІ-юрист — це інтелектуальна RAG (Retrieval-Augmented Generation) система, реалілізована у вигляді Telegram-бота. Вона призначена для пошуку, аналізу та трактування законодавства України, а також для надання статистичної аналітики на основі актуальних даних з порталу Верховної Ради.

Система побудована на надійній архітектурі мікросервісів, що забезпечує масштабованість, стабільність та керованість.

🏗️ 1. Архітектура Системи (Мікросервіси)

Система працює як єдиний оркестрований комплекс з трьох основних Python-сервісів, які взаємодіють через PostgreSQL/pgvector та Telegram API.

Опис компонентів:

1. Database (database_setup.py)

Роль: Сховище всіх даних.

Функції: PostgreSQL з розширенням pgvector. Зберігає тексти законів, вектори (embeddings), метадані, історію діалогів та системні налаштування (SystemConfig).

2. Worker (worker_rada.py)

Роль: Обробник черги та Векторизатор.

Функції: Завантажує контент з черги (status=pending), очищає HTML, розбиває на ієрархічні чанки, генерує вектори (Gemini Embeddings) та записує їх у БД.

3. Collector (collector_rada.py)

Роль: "Павук" та Монітор.

Функції: Погодинно моніторить першу сторінку ВР на нові документи, ініціює повний парсинг за командою з бота та ставить нові документи у чергу (status=pending) для Worker.

4. Bot (bot.py)

Роль: Інтерфейс та FSM-менеджер.

Функції: Керує станами користувача, обробляє команди Адміна, надсилає запити до RAG-сервісу.

5. RAG Service (rag_service_v3.py)

Роль: Інтелект системи.

Функції: Виконує аналіз намірів, Гібридний пошук (Vector + FTS/SQL), реранкінг знайдених чанків та генерує фінальну юридичну консультацію (Gemini LLM).

6. Manager (main.py)

Роль: Оркестратор.

Функції: Запускає всі три основні сервіси (worker, collector, bot) у фоновому режимі та забезпечує їхній автоматичний перезапуск у разі падіння.

🚀 2. Основні можливості та Інновації

1. 🧠 Гібридний Пошук (Hybrid Search Engine)

Система використовує найсучасніший підхід, поєднуючи точність та семантику:

Vector Search (Semantic): Пошук за змістом, розуміння контексту запиту (наприклад, "покарання за хабар" -> статті ККУ про неправомірну вигоду).

Full-Text Search (FTS): Швидкий пошук за ключовими словами.

SQL Lookup: Точний пошук за номером статті та назвою закону, що унеможливлює "галлюцинації".

FlashRank Reranking: Фінальне пересортування знайдених документів для максимальної релевантності перед подачею в LLM.

2. 🌐 Розумний ETL та Моніторинг

Погодинна перевірка: collector_rada.py автоматично сканує перші сторінки ВР раз на годину, щоб швидко виявляти нові закони.

DB-Controlled State: Використання таблиці system_config для керування станом парсера з Telegram (заміна старих, нестабільних файлів стану).

Ієрархічний чанкінг: Текст розбивається логічно (Стаття, Розділ, Глава) для збереження контексту в кожному чанку.

3. 🗣️ Адаптивна Пам'ять Діалогу (Contextual Awareness)

Динамічне резюме: У режимі "Мої справи" бот формує та оновлює коротке резюме (summary) всієї розмови, дозволяючи підтримувати контекст без перевантаження LLM.

HTML-Форматування: Використовується конвертація Markdown-відповіді LLM у HTML-розмітку Telegram, що зберігає посилання та структуру тексту.

🤖 3. Команди та Режими Бота (bot.py)

Бот має два основні режими роботи для користувача та окрему, захищену Адміністративну панель.

А. Основні режими користувача

1. Швидка відповідь (Кнопка: ⚡ Швидка відповідь)

Режим для одноразових, незалежних запитань. Історія діалогу не зберігається.

2. Мої справи (Кнопка: 📂 Мої справи)

Контекстний режим. Дозволяє створювати, видаляти та продовжувати справи. Система зберігає та оновлює контекст розмови.

3. Керування справами (Кнопки: ➕ Створити справу, ❌ Видалити справу)

Стандартні функції CRUD для керування збереженими контекстними діалогами.

Б. Команди Адміністратора (Доступ лише через ADMIN_IDS)

Ці команди керують станом сервісу collector_rada.py через Адмін-панель (кнопка ⚙️ Панель Адміністратора).

1. Керування парсингом:

Примусова перевірка (Кнопка: ⚡ Force Run (Scan 1-5)): Негайно запускає колектор для перевірки перших 5 сторінок (нових документів), незалежно від часу останнього запуску.

Повний парсинг (Кнопка: 📚 Повний парсинг (Reset All)): Встановлює режим collector_mode='full' та скидає лічильник сторінок (current_page) на 1. Це ініціює повне сканування сайту ВР з самого початку.

Нормальний режим (Кнопка: ⏰ Режим 'Щогодини'): Встановлює режим collector_mode='hourly'. Колектор перевірятиме нові документи раз на годину.

Зупинка (Кнопка: 🛑 Зупинити Колектор): Встановлює режим collector_mode='stop'. Колектор припиняє парсинг та очікує.

2. Моніторинг:

Статус (Кнопка: 🔄 Оновити статус): Оновлює інформацію про поточний режим, сторінку парсингу та час останнього запуску.

🛠️ 4. Встановлення та Ініціалізація Бази Даних

Крок 1: Запуск Docker-контейнера PostgreSQL + pgvector

Для розгортання бази даних з підтримкою векторів використовуйте наступну команду:

docker run --name ai-lawyer-db \
-e POSTGRES_USER=postgres \
-e POSTGRES_PASSWORD=my_secret_pass_123 \
-e POSTGRES_DB=law_db \
-p 5433:5432 \
-d pgvector/pgvector:pg16


Примітка: Рекомендовано використовувати версію pgvector:pg16 або pg15. Порт 5433 використовується для уникнення конфлікту з локальним PostgreSQL.

Крок 2: Увімкнення розширення vector

Після запуску контейнера активуйте необхідне розширення у базі law_db:

docker exec -it ai-lawyer-db psql -U postgres -d law_db -c "CREATE EXTENSION IF NOT EXISTS vector;"


Крок 3: Конфігурація .env

Переконайтесь, що ваш файл .env містить коректні дані для підключення та авторизації:

DATABASE_URL=postgresql://postgres:my_secret_pass_123@localhost:5433/law_db
GOOGLE_API_KEY=AIzaSy...
BOT_TOKEN=123456:ABC...

# Ваш Telegram ID
ADMIN_IDS=ВАШ_ОСОБИСТИЙ_ID_ДЛЯ_АДМІН-ПАНЕЛІ


Крок 4: Ініціалізація структури БД та Міграція

Запустіть скрипт міграції (migrate_db.py) для створення всіх таблиць, полів та індексів (HNSW, GIN):

python migrate_db.py


Фінальний запуск системи: Запустіть головний менеджер системи:

python main.py


main.py забезпечить запуск та автоматичний моніторинг усіх мікросервісів.
